## 题目描述

假设你是一位很棒的家长，想要给你的孩子们一些小饼干。但是每个孩子最多只能给一块饼干。

对于每个孩子 `i`，都有一个胃口值 `g[i]`，这是能让他们满足的最小饼干尺寸。每块饼干 `j` 都有一个尺寸 `s[j]`。如果 `s[j] >= g[i]`，我们可以将这块饼干 `j` 分配给孩子 `i`，这个孩子会得到满足。

你的目标是满足尽可能多的孩子，并输出这个最大数值。

### 示例

```
输入：g = [1,2,3], s = [1,1]
输出：1
解释：
你有三个孩子和两块小饼干，3 个孩子的胃口值分别是：1, 2, 3。
虽然你有两块饼干，但尺寸都是 1，只能让胃口值为 1 的孩子满足。
所以输出 1。

输入：g = [1,2], s = [1,2,3]
输出：2
解释：
两个孩子胃口值为 1, 2，饼干尺寸为 1, 2, 3。
尺寸 1 给胃口 1，尺寸 2 给胃口 2 → 两个都满足。
```

### 约束

- `1 <= g.length <= 3 * 10^4`
- `0 <= s.length <= 3 * 10^4`
- `1 <= g[i], s[j] <= 2^31 - 1`

---

## 解题思路

### 核心思想：排序 + 双指针贪心

贪心策略：**用最小的饼干去满足胃口最小的孩子**。如果当前最小的饼干不能满足这个孩子，说明这块饼干谁也满足不了——直接丢弃，换下一块更大的。

```
1. 将孩子胃口 g 和饼干尺寸 s 分别排序（升序）
2. 双指针：child 指向当前孩子，cookie 指向当前饼干
3. 如果 s[cookie] >= g[child] → 当前饼干可以满足该孩子，两个指针都后移
   如果 s[cookie] <  g[child] → 饼干太小，丢弃这块饼干，cookie 后移
4. child 的值就是最终满足的孩子数
```

### 为什么贪心是对的

**贪心选择性质**：对于胃口最小的孩子，给他能满足他的最小饼干，不会使全局结果变差。因为这块饼干给其他胃口更大的孩子「值不值得」不确定，但给最小的孩子一定不浪费。

### 推演示例（g = [1,2,3], s = [1,2]）

```text
排序后：
  g = [1, 2, 3]
  s = [1, 2]

child=0 (g=1), cookie=0 (s=1): s[0] >= g[0] ✓ → 都 +1，child=1
child=1 (g=2), cookie=1 (s=2): s[1] >= g[1] ✓ → 都 +1，child=2
child=2 (g=3), cookie=2       : 饼干耗尽

结果：child = 2（满足两个孩子）
```

### 复杂度分析

| 维度 | 复杂度 |
|------|--------|
| 时间 | O(n log n + m log m) — 排序占主导，双指针遍历 O(n + m) |
| 空间 | O(log n + log m) — 排序的递归栈深度 |

## 代码实现

### Java

```java
import java.util.Arrays;

class Solution {
    public int findContentChildren(int[] g, int[] s) {
        Arrays.sort(g);  // 孩子胃口升序
        Arrays.sort(s);  // 饼干尺寸升序

        int child = 0;
        int cookie = 0;

        // 双指针：遍历饼干，尝试满足孩子
        while (child < g.length && cookie < s.length) {
            if (s[cookie] >= g[child]) {
                child++;   // 当前饼干满足该孩子，孩子指针后移
            }
            cookie++;      // 饼干无论是否使用，都移向下一块
        }

        return child;
    }
}
```

**写法要点**：
- `cookie++` 放在 `if-else` 之外——无论是否满足，饼干都被消耗（太小的没法满足任何人）
- `child` 只在满足时递增，最终 `child` 的值就是满足的总数
- 不需要额外的 `count` 变量，`child` 指针位置就是答案

---

## 关键点总结

1. **贪心策略选择**：用最小的饼干满足最小的需求——这是最大匹配的经典贪心
2. **排序是前提**：不排序无法保证「当前最优」能导出「全局最优」
3. **双指针技巧**：`child` 和 `cookie` 各自独立移动，逻辑清晰且 O(n+m)
4. **贪心正确性**：如果小饼干连胃口最小的孩子都满足不了，它不可能满足任何孩子
5. **与 #135 的区分**：#455 的贪心基于排序比较大小；#135 分发糖果是左右两次扫描的贪心，更复杂
