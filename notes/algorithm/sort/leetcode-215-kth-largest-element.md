# LeetCode 215 - Kth Largest Element in an Array（数组中的第 K 个最大元素）

> 第 K 大元素是 Top K 问题的经典变体——用小顶堆维护固定的 k 个最大候选，堆顶即为答案。本文以堆解法为核心，对比快速选择、排序等替代方案。

## 题目描述

给定整数数组 `nums` 和整数 `k`，返回数组中第 `k` 个最大的元素。注意是排序后的第 k 个最大，不是第 k 个不同元素。

```
示例 1:
输入: nums = [3,2,1,5,6,4], k = 2
输出: 5
解释: 排序后 [1,2,3,4,5,6]，第 2 大是 5

示例 2:
输入: nums = [3,2,3,1,2,4,5,5,6], k = 4
输出: 4
```

约束：`1 <= k <= nums.length <= 10^5`，`-10^4 <= nums[i] <= 10^4`

---

## 解题思路

三种解法从简单到最优——面试时优先熟练掌握堆解法，进阶可以补充快速选择。

核心策略：用一个大小为 `k` 的小顶堆维护「当前看到的最大的 k 个元素」，遍历结束后堆顶就是第 k 大。

维护一个大小为 `k` 的小顶堆。遍历数组时将元素入堆，堆超过 k 个就弹出堆顶（最小值）。遍历结束后堆中保留的就是最大的 k 个元素，堆顶即为第 k 大。

```text
nums = [3,2,1,5,6,4], k = 2

遍历 3: 堆 = [3]
遍历 2: 堆 = [2, 3]
遍历 1: 堆 = [2, 3] → 超过 k，弹 1
遍历 5: 堆 = [2, 3, 5] → 弹 2，堆 = [3, 5]
遍历 6: 堆 = [3, 5, 6] → 弹 3，堆 = [5, 6]
遍历 4: 堆 = [4, 5, 6] → 弹 4，堆 = [5, 6]

堆顶 = 5 → 第 2 大 ✓
```

### 为什么用小顶堆而不是大顶堆？

**用小顶堆的核心原因：我们需要淘汰的是「不够大」的元素。**

小顶堆的堆顶是堆中最小值。当堆满 k 个时，新元素比堆顶小 → 说明它不可能是前 k 大，直接丢弃；新元素比堆顶大 → 弹出堆顶这个「前 k 大中最小的」，把新元素加进去。堆顶始终是「第 k 大的门槛」，低于门槛的就淘汰。

```
大顶堆为什么不行？——堆顶是最大值，淘汰谁？
  因为淘汰堆顶等于丢掉最大的，保留下来的反而是小的。
  要维持 Top K 最大，我们需要淘汰的是最小的，正好是小顶堆 heap[0]。
```

一句话：**堆顶 = 淘汰候选，要找第 K 大 → 淘汰小的 → 用小顶堆**。对称地，要找第 K 小 → 淘汰大的 → 用大顶堆。

## 代码实现

```java
class Solution {
    public int findKthLargest(int[] nums, int k) {
        // 小顶堆——堆顶始终是堆中最小的
        PriorityQueue<Integer> minHeap = new PriorityQueue<>();

        for (int num : nums) {
            minHeap.offer(num);
            if (minHeap.size() > k) {
                minHeap.poll();     // 弹出最小值，保持堆大小为 k
            }
        }
        return minHeap.peek();      // 堆中剩 k 个最大元素，堆顶即第 k 大
    }
}
```

## 关键点总结

1. **小顶堆维护 Top K**：堆顶是候选集合中的最小值，始终保持 k 个「最大」的元素——这是 Top K 问题的通用模板
2. **堆大小超过 k 就弹**：`size > k → poll()` 保证堆永远只有 k 个元素，空间 O(K)
3. **第 K 大 ≠ 第 K 小**：第 K 大 = 第 `n - k + 1` 小（排序后下标 `n - k`），堆解法绕过了这个换算
4. **堆的 Comparator**：找第 K 大用小顶堆，找第 K 小用大顶堆——选反了就错了
