## 题目描述

给定一个整数数组 `nums`，除某个元素仅出现**一次**外，其余每个元素都恰出现**三次**。请你找出那个只出现了一次的元素。

要求：设计并实现**线性时间复杂度**且**不使用额外空间**的算法来解决此问题。

### 示例

```
输入：nums = [2,2,3,2]
输出：3
```

```
输入：nums = [0,1,0,1,0,1,99]
输出：99
```

### 约束

- `1 <= nums.length <= 3 * 10^4`
- `-2^31 <= nums[i] <= 2^31 - 1`
- 除某个元素只出现一次外，其余每个元素都恰出现三次

---

## 解题思路

### 核心思想：按位统计 + 取模

一个数若出现 3 次，那么它的**每一个二进制位上的 1 也都会出现 3 次**。反过来想：如果把所有数字在**同一位**上的 1 加起来：

- 出现 3 次的那些数，贡献的 1 的个数是 3 的倍数；
- 只有那个「只出现一次」的数，会让某些位上的计数**多出 1**（即 `bitCount % 3 != 0`）。

于是逐位扫描 32 个 bit，统计所有数字在该位上的 1 的总数，`mod 3` 后剩下的就是目标数在该位的值：

```
for bit in 0..31:
    bitCount = Σ (nums[i] >> bit) & 1      // 统计所有数第 bit 位
    if bitCount % 3 != 0:
        result |= (1 << bit)                 // 该位属于目标数
```

### 为什么能处理负数

- `>>` 是**算术右移**：负数右移高位补符号位 1。但 `(x >> bit) & 1` 只取**最低位**，无论高位怎么补，`& 1` 后得到的都是原数第 `bit` 位的值，所以负数照样正确。
- 还原时 `1 << 31` 会得到一个负数（恰好是符号位 `INT_MIN`），这**正是**负数第 31 位的正确表示——`result` 最终能完整还原出负数目标值，无需特判。

### 复杂度分析

| 解法 | 时间 | 空间 |
|------|------|------|
| 按位统计 | O(32·n) = O(n) | O(1) |

## 代码实现

### Java（按位统计）

```java
class Solution {
    public int singleNumber(int[] nums) {
        if (nums == null || nums.length == 0) {
            return 0;
        }

        int result = 0;
        for (int bit = 0; bit < 32; bit++) {
            int bitCount = 0;
            for (int num : nums) {
                // 关键：取的是当前数字 num 的第 bit 位，不是 nums[bit]
                bitCount += (num >> bit) & 1;
            }

            // 该位 1 的个数不是 3 的倍数 → 属于目标数
            if (bitCount % 3 != 0) {
                result |= (1 << bit);
            }
        }

        return result;
    }
}
```

---

## 关键点总结

1. **按位统计的本质**：出现 3 次的数，每一位的 1 都是 3 的倍数；`mod 3` 后剩下的就是目标数的位——把「数字出现次数」问题降维成「每一位 1 的个数」问题
2. **下标别写错**：内层循环取的是**数组元素** `nums[numIndex]`（增强 for 里的 `num`），不是位下标 `index`——这是本题最常见的笔误
3. **负数无需特判**：`(num >> bit) & 1` 只取最低位，算术右移的符号位填充不影响结果；`1 << 31` 得到 `INT_MIN` 恰好正确还原负数
4. **通用性**：此思路可推广到「其余元素出现 k 次」——逐位统计后 `mod k` 即可，k=2 时退化为经典异或（#136）
